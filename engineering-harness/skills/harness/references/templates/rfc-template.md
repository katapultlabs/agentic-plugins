# RFC Template

Copy this file as `docs/rfcs/RFC-NNN-short-name.md` when proposing a
design that needs team review before implementation. RFCs are for
proposals that are too big or cross-cutting for a single person or
agent to decide alone.

---

```markdown
# RFC-NNN: [Proposal Title]

**Author:** [Name]
**Date:** [YYYY-MM-DD]
**Status:** Draft | In Review | Accepted | Rejected | Superseded
**Reviewers:** [Names — aim for 2-3 reviewers with relevant expertise]
**Linear Issue:** [Link to tracking issue if applicable]

## Summary

[One paragraph: what are you proposing and why? A busy reader should
be able to decide whether to keep reading from this paragraph alone.]

## Motivation

[Why is this change needed? What problem does it solve? What happens
if we do nothing? Include data or examples if you have them.]

## Detailed Design

[The meat of the proposal. How will it work? Include:
- Architecture and system interactions
- API contracts or interface changes
- Data model changes
- Migration strategy if applicable

Be specific enough that an engineer or agent could implement from this
document, but don't over-specify implementation details that should be
left to the implementer.]

## Tradeoffs and Alternatives

[What other approaches did you consider? Why is this one better?
What are we giving up?]

## Rollout Plan

[How will this be shipped? Feature flag? Phased migration? Big bang?
What's the rollback strategy if something goes wrong?]

## Open Questions

- [Things you want reviewer input on]
- [Decisions you're not sure about]

## Review Log

| Date | Reviewer | Feedback | Resolution |
|------|----------|----------|------------|
| | | | |
```
